原来的个人交接说明及个人使用文档不随包分发，公开说明重新撰写。本机配置、登录请求、日志、历史报告和浏览器存储同样不分发。

## 公开版测试改动

JavaScript 测试改为相对于自身位置查找源码；去掉生成 key、写回 ID 和写入“浏览器尚未验证”报告的逻辑。保留 8 组行为检查：manifest 声明、严格 URL 匹配、自建后台标签页与默认搜索 API、模拟 Bing 失败、API 异常清理、请求去重、失败后只重载一次、重载后的再次验证。

PowerShell 测试改为相对于仓库定位脚本，在系统临时目录创建独立测试夹具，保留原子 JSON 替换和扩展持久状态识别检查。测试从 AST 取出两个函数，不执行 `Install`、`Request` 或 `Uninstall`。它只在控制台输出测试结果，不覆盖运行目录的历史报告。解析器检查会报告实际 PowerShell 版本，不能把 PowerShell 7 的通过表述为 Windows PowerShell 5.1 实测。

另有发布完整性检查，校验原始运行文件哈希、固定扩展身份及发布白名单。修改运行逻辑后，应更新版本、重新验证并明确更新基线，不能无说明地替换原始哈希。

## 新安装的真实检查

1. 正常安装并启用扩展。
2. 运行 `Verify.cmd`，查看当前 `Extension/login-request.json` 的 `id`。
3. 在运行中的目标 Edge 配置文件里等待约一分钟，查看弹窗或导出结果。核对 `ok=true`、结果 `requestId` 与当前请求一致、`checkedAt` 晚于请求创建时间。
4. 若需要验证登录任务，再正常注销登录或重启。比较这次开机、任务运行、新请求及新结果的时间顺序；旧的 `OK` 不能代替本次结果。

本指南说明验证方法，不会因读文档或运行代码测试而自动重启系统。

## 保留的限制

- 扩展禁用后不会被强制重新启用。
- 没有测试真实改为 Bing 后的恢复，也没有测试竞争扩展、浏览器后续机制变化或有系统权限的程序。
- 一次安装只覆盖一个配置文件。固定任务名也限制了同用户多实例并行安装。
- 只检查默认搜索生成的目标导航，不证明页面加载或网络可达。
- 手动验证 ID 没有持久化在请求文件中。手动失败重载后可能转而处理登录请求；这是代码阅读发现的候选问题，未复现实测。
- 不分发临时 LevelDB 日志提取器；读取任意旧 `ok=true` 不能证明当前请求通过。需要结果时优先使用扩展弹窗导出。

## 当前使用者的维护

此版本的运行脚本、扩展公钥和 ID 没有变化，现有安装无需重装或重新加载。不要把分享包覆盖到原运行目录来“刷新状态”。修改扩展代码后才需要在 Edge 中手动重载；不应重新生成 key。卸载任务必须从原安装目录执行，再手动移除扩展。
